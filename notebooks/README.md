# DSDL notebooks

The Jupyter notebooks that the DSDL container images ship. In a DEV container they open in JupyterLab (open this file
there with right-click > Open With > Markdown Preview). When a notebook is saved, its DSDL cells (import, stage, init,
fit, apply, save, load, summary) are exported to `/srv/app/model/<notebook>.py`, and `| fit MLTKContainer algo=<notebook> ...`
and `| apply` run that module. Many notebooks keep the template's example SPL (`algo=barebone` or `algo=barebone_template`):
always use `algo=<notebook>`, also with `mode=stage`. This file ships in the images too, as `/srv/notebooks/README.md`, and like
the notebooks it is replaced at every container start.

The table maps every notebook to the 5.2.5 images it works with. **How this was determined:** the top-level packages that
every notebook imports were checked for presence inside each built image, and the smoke test imports every exported
`/srv/app/model` module in every image. Then each notebook's code was reviewed against the library versions of the images,
and single stages of some notebooks were run in the images to settle doubtful cases. The notebooks were **not** run end to
end, except where a note says so. Status as of 2026-10-27.

| Column | Images (`images.conf` stanzas) |
|---|---|
| cpu | `golden-cpu`, `golden-cpu-arm`, `escu-cpu`, `golden-cpu-transformers` |
| llm / agentic | `llm-rag`, `agentic-ai` (the same libraries) |
| gpu | `golden-gpu`, `golden-gpu-transformers` (they also run without a GPU) |
| rapids | `golden-gpu-rapids` (no TensorFlow, no spaCy, pandas 3) |
| spark | `spark` (the cpu content plus PySpark 4.2) |

✓ works · ◐ partly (see notes) · – does not work · ? untested whether it works

**Status:** Working (28) needs nothing beyond the image and Splunk data · Prerequisites (37) works once the prerequisites in the notes are met (a service, a model download, data, a GPU or a change to the notebook). "`| fit` only": `| fit` returns results, but a later `| apply` of the saved model fails (the model is not saved, or load cannot restore it). "`| apply` only": runs a pretrained model, there is nothing to fit. Start-up replaces the shipped notebooks (and their `/srv/app/model` modules) with the image's copies, so make a change that a note asks for in a copy under a new name and call it with `algo=<copy>`. The 8 notebooks that cannot be used as shipped in any 5.2.5 image are in [`deprecated/`](deprecated/) (see [Deprecated notebooks](#deprecated-notebooks) below).

## Deprecated notebooks

These notebooks are in [`deprecated/`](deprecated/) and cannot be used as shipped in any 5.2.5 image; they are kept for
reference. Six of them still have their exported module in `/srv/app/model/` (`conf25_BYO_AI_XGBoost_onnx_dsdl` and
`spacy_ner_ja` have none), so a search or DSDL example dashboard that calls `algo=<name>` fails for the reason in the table
below. Apply a possible fix in a copy under a new name, as above. A volume used by an earlier image still holds their old
copies at the top level of `/srv/notebooks` (start-up never deletes files); delete them by hand. The notebooks removed before
5.2.5 (`autosklearn_classification`, `river_halfspacetree`) are in the source repository's top-level `deprecated/notebooks/`
folder and are not part of the images.

| Notebook | What it did | Why it no longer works | Possible fix |

- `intent_detection_bert.py`, `intent_detection_rouge.py`: exports of notebooks whose `.ipynb` is not in the repository
  (identical to `/srv/app/model/`). `intent_detection_bert` needs the Japanese BERT base model in
